Elliott Wave (illustrative only)

Mechanically generated, not in composite — see caveat below
BTC price Zigzag swing (% reversal filter)
This is not a validated Elliott Wave count. Elliott Wave analysis is inherently subjective — trained analysts routinely disagree on the same chart. What's plotted here is a purely mechanical swing detector (a zigzag filter that marks a new pivot whenever price reverses by more than the threshold shown) with the classic 1-2-3-4-5-A-B-C labels applied by counting pivots in order and cycling every 8. It does not check any actual Elliott rule (wave 2 can't retrace past wave 1's start, wave 3 is never the shortest, wave 4 shouldn't overlap wave 1, alternation, Fibonacci ratios) and has no concept of nested sub-waves, truncations, or extensions. Treat the labels as "one arbitrary count a simple algorithm produced," not a claim about the real wave structure — a different reversal threshold would produce an entirely different count.

Data: blockchain.info (BTC price), Fear & Greed Index blended from alternative.me (history before ~June 2023) and CoinMarketCap (from that point forward), Bitcoin Supply in Loss % and MVRV Ratio from BGeometrics (MVRV's free history only goes back to ~Sept 2022). Composite = 200-week MA distance (5%), 7d-smoothed Fear & Greed (30%), weekly RSI (30%), Bitcoin Supply in Loss % (30%), and MVRV Ratio (5%), each normalized 0–100. By explicit request, Pi Cycle Top ratio was removed and Supply in Loss % / MVRV Ratio added in its place, and the weights above were rebalanced away from equal 20% each — walk-forward testing found none of these changes improved the composite's forward-return signal, and the rebalance made it worse again (equal-weighted with Pi Cycle removed tested at 0.9pp TRAIN / 0.8pp spread vs. 10.3pp/10.3pp for the Pi-Cycle-based composite it replaces; the current 5/30/30/30/5 weighting tests at -18.7pp TRAIN / -7.2pp TEST — every threshold config swept came back negative on TRAIN, there was no config left to even optimistically cherry-pick); it's live anyway, by explicit request, fully informed, the same way Dashboard 2 already ships a composite that isn't separately validated — see the README's "Removing Pi Cycle Top, adding Supply in Loss %", "Adding MVRV Ratio despite its short history", and "Rebalancing LIVE_WEIGHTS (5/30/30/30/5)" for the full comparisons. Separately: the 7-day Fear & Greed smoothing window is also an experimental variant — the validated 30-day window scored higher on its own (10.3pp vs. 7.8pp TRAIN spread, tested before the changes above). The dashed 21w/34w EMA lines (a trader Alessio Rastani-style support structure) are shown for context only — testing found adding them to the composite weakened out-of-sample performance, so they're tracked but not scored; see the README's "Why the EMA structure indicator isn't in the default weighting."
